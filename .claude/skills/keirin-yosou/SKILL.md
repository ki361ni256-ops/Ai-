# 競輪予想の仕組み（貼る → 予想 → 記録 → 結果 → 振り返り）

ルールは CLAUDE.md が最上位。とくに「推測でデータを作らない」「根拠のない収益性を言わない」を守る。

## 1. 予想（出走表のテキストが貼られたとき）
1. 会場・日付・レース番号を確認する（書いていなければ聞く。日付は今日と決めつけない）
2. 貼られた出走表をそのまま `予想記録/inputs/<会場>_<YYYYMMDD>_<RR>R_card.txt` に保存。オッズも貼られたら `..._odds.txt` に保存
3. `python3 scripts/yosou.py predict <会場> <YYYY-MM-DD> <R> <card.txt> [odds.txt]` を実行
4. `ok: false` なら、problems をそのまま伝えて止まる（読めなかった項目を推測で補わない）
5. 出力の x_text をコピペできる形で返す。x_audit に指摘があれば直してから返す
6. 予想は印・買い目を機械的に出したもの。**オッズを見ていないときは「荒れる」「堅い」「妙味」を書かない**（オッズが貼られたら、買い目のオッズと人気順を添える）
7. 「AI予想」とは書かない（モデルは未検証）。「出走表から読む予想（ルール v1）」と書く
8. 投稿文には注意書きを入れない（2026-10-09 本人指示）。代わりに並び・オッズ表のコメント等、分かっている情報から**展開を1〜2行**で書き、`render_x(..., tenkai=...)` に渡す。並びが分からないときは展開を書かない（想像で作らない）
9. 買い目はフォーメーション表記（例 1-25-25）でまとめる（compress が自動で行う）。買い目は「厚め・本線・押さえ」の3区分だけ。「荒れた場合」「ライン決着なら」などの追加の買い目は出さない（2026-10-09 本人指示）
10. `予想記録/inputs/` と `yosou.db` を commit・push する（作業環境は使い終わると消えるため、DB も Git に残す）

## 1.5 チェック（予想を作るたびに必ず）
- 投稿文を出す前に、チェック担当（`.claude/agents/keirin-checker.md`）に「A. 投稿前チェック」を頼む
- 判定が「要修正」なら直してから本人に返す。返すときに、チェック担当のひとことを1行添える

## 2. 結果（「結果：弥彦 8R 1-5-2 12340円」のように送られたとき）
- `python3 scripts/yosou.py result <会場> <YYYY-MM-DD> <R> <3連単> [払戻]`
- 払戻が分からなければ省略してよい（回収率の計算から外れる。推測で入れない）
- 記録したら、チェック担当に「B. 結果のあとのフィードバック」を頼み、`予想記録/チェック記録.md` に追記する
- 結果報告の投稿文を作るときも、文字数チェック（280以内）を通す

## 3. 振り返り（「振り返り」と言われたとき）
- `python3 scripts/yosou.py report` を実行し、区分（厚め・本線・押さえ・合計）ごとの的中率・回収率・最大連敗・最大ドローダウンを表で返す
- 監査の指摘（サンプル不足、発走後の予想、投稿文の問題、入力ファイルの改ざん）を必ず添える
- **結果が100レース未満のうちは、回収率から良し悪しを結論づけない**

## 4. ルールの改善（品質改善ループ.md）
- 改善案は `keirin/yosou.py` の RULES に新しいバージョン（v2 …）として追加し、v1 は消さない
- `python3 scripts/yosou.py compare v1 v2` で、保存済みの出走表に両方を当てはめて比べる
- adopt が true（100レース以上で回収率が上がる）になるまで CURRENT を切り替えない
- 比べた結果は 品質改善ループ.md の「変更履歴」に書く
